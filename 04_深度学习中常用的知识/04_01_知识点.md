

# 1 **AI / 深度学习中常用的数值精度（数据类型）大全**，包括 **浮点数和整数**


你问的 “数值精度值” 在 AI / 深度学习 中，主要指 不同精度类型能表示的数值范围和精度



**FP16** = 16-bit floating point（半精度浮点数）

|精度类型|位宽|特点|应用场景|
|---|---|---|---|
|**FP32**（单精度）|32|精度高，数值稳定|训练大部分模型、需要高精度计算|
|**FP16**（半精度）|16|精度降低，显存占用减半，计算加速|推理、混合精度训练|
|**BF16**（Brain FP16）|16|指数位和 FP32 一样，尾数精度低|GPU/TPU 混合精度训练，保持数值稳定性|
|**FP64**（双精度）|64|高精度，数值范围大|科学计算、高精度模拟，不常用于深度学习|
|**FP8**（最近研究型）|8|精度低，但速度快，显存占用极小|AI 推理加速、超大模型，部分实验性 GPU 支持|

|精度类型|位宽|特点|应用场景|
|---|---|---|---|
|**INT8**|8|精度低，显存占用小，推理加速明显|模型量化推理、边缘设备部署|
|**INT4**|4|精度更低，占用更少显存|超大模型量化实验，主要用于推理|
|**INT1 / Binary**|1|二值化|极端压缩/加速模型，少见|

|类型|位宽|特点|应用场景|
|---|---|---|---|
|**FP16/FP32 混合精度**|16+32|用 FP16 计算加速，FP32 保留累加器|深度学习训练加速，常用 NVIDIA Apex / PyTorch AMP|
|**TensorFloat-32 (TF32)**|19 (GPU 特定)|类似 FP32 精度，但计算更快|NVIDIA A100 / Hopper GPU 上训练 Transformer|
|**Quantized Float / FP8E4M3**|8|FP8 的一种格式|NVIDIA Hopper / LLM 推理加速实验|


- **训练时常用**：FP32、FP16、BF16、混合精度
    
- **推理加速**：FP16、BF16、INT8、INT4、FP8
    
- **高精度科学计算**：FP64
    
- **超低精度实验/超大模型**：FP8、INT4、Binary


## 1.1 FP16 用 16 位存储一个浮点数，分为三个部分：

|部分|位数|作用|
|---|---|---|
|**符号位 (sign)**|1|表示正负，0 = 正数，1 = 负数|
|**指数位 (exponent)**|5|控制浮点数的数量级（大/小）|
|**尾数位 / 小数部分 (mantissa / fraction)**|10|控制精度，相当于有效数字|


 符号位 (1 bit)
- 决定数的正负
- 例子：
    - 0 → 正数
    - 1 → 负数

 指数位 (5 bits)
- 用来表示数的 **数量级**
- FP16 指数采用 **偏移二进制 (biased)** 表示法
    - 偏移量为 15（即 exponent = 真值 + 15）
- 指数范围：
    - 真值范围：-14 到 +15
    - 对应 FP16 可表示的最大/最小数值

尾数位 / 有效数字 (10 bits)
- 尾数表示 **数的精度**，决定小数部分精确度
- 在 FP16 里：
    - 默认有一个 **隐藏的最高位 1**（normalized number）
    - 实际精度 ≈ 10 位二进制 → 大约 3 个十进制有效数字


![](image/Pasted%20image%2020250825120743.png)

- **1 位符号** → 控制正负
    
- **5 位指数** → 控制数值大小（数量级）
    
- **10 位尾数** → 控制精度（有效数字）
    
- FP16 精度比 FP32 低，但占用显存少，适合 AI 推理或混合精度训练


# 2 量化中的校准表

“主要用于计算激活分布，从而确定量化 scale/zero-point 或校准表”  
👉 意思是：我们用一个小的 **Calibration dataset** 来统计模型各层输出值的范围，再根据这些范围计算出合适的量化参数（scale/zero-point），并保存成校准表，供后续 INT8 推理使用。



在 量化 (quantization) 里，我们要把浮点数（FP32/FP16）压缩成低精度整数（INT8），减少存储和加速推理。

例子：把 [-3.2, 5.7] 之间的浮点数映射到 INT8 的 [-128, 127]。

要做到这一点，就需要知道这些数值通常落在哪个范围里，否则会出现溢出或精度损失。


## 2.1 ## 什么是 **激活分布 (activation distribution)**

- **激活 (activation)** 指的是神经网络中间层算子的输出值。
    
- 比如：卷积层 → ReLU → 输出一个张量，这个张量里的值就是“激活”。
    
- **分布 (distribution)** 指的是这些值的统计范围和分布情况，比如：
    
    - 最小值 / 最大值
        
    - 平均值 / 标准差
        
    - 直方图形态（例如大部分值集中在 [-1, 1] 区间）
        

👉 简单说：**激活分布就是神经网络输出的数值范围和分布规律**。

- **r**：原始浮点数（real value）
    
- **q**：量化后的整数（quantized value）
    
- **scale**：缩放因子（控制分辨率，float → int 的比例尺）
    
- **zero-point**：零点偏移（保证 0 可以被精确表示）
    

👉 举个例子：

- 激活分布范围是 [–2.5, 3.5]
    
- 选定量化范围为 INT8 [–128, 127]
    
- 那么 scale ≈ (3.5 - (–2.5)) / (127 - (–128)) ≈ 6 / 255 ≈ 0.0235
    
- zero-point 决定浮点 0 对应的整数位置（偏移量）。

## 2.3 校准表 (Calibration Table)

- 当你用 **Calibration dataset** 跑一遍模型，统计每一层激活的分布（min/max 或直方图）。
    
- 框架会根据这些分布，计算出每一层的 **scale 和 zero-point**。
    
- 最终结果就是一个 **校准表 (calibration table)**，里面存了所有层的量化参数。
    
- 在真正的量化推理（INT8 inference）时，就用这个表来完成浮点到整数的映射。

# 3 ONNX

ONNX 就像“深度学习模型的通用语言”，让不同框架之间互通，方便模型迁移和部署。
ONNX 也是个“框架/标准”，不是某个模型。它全称是 Open Neural Network Exchange，可以理解成一种 深度学习模型的通用格式。
让不同深度学习框架之间的模型可以互相转换、兼容。

以前的问题是：
- PyTorch 训练的模型 → 只能在 PyTorch 里用    
- TensorFlow/Keras 的模型 → 只能在 TensorFlow 里用

这样部署就麻烦。ONNX 解决了这一点：
1. 把 PyTorch/TensorFlow/MXNet 等框架的模型 **导出** 为 ONNX 格式    
2. 然后任何支持 ONNX 的推理引擎（如 TensorRT、OpenVINO、ONNX Runtime）都能直接加载和运行

分析总结目前国际主流软硬件能力测试基准情况（如[MLPerf](https://zhida.zhihu.com/search?content_id=242670823&content_type=Article&match_order=1&q=MLPerf&zhida_source=entity) 等），包括但不限于基准发起背景、测试思路、主要测试内容和指标、行业影响等。

# 1 基准情况



**AI Benchmark**。
AI Benchmark[23]可以说是第一个移动推理基准套件。它的结果和排行榜主要关注**Android智能手机**，只衡量**延迟**。套件提供了一个总结分数，但是它不能明确地指定质量目标。我们的目标是各种设备(我们提交的范围从物联网设备到智能手机和边缘/服务器规模的系统)以及每个基准测试的四个场景。
- **定位**：第一个专门面向 **移动推理** 的基准套件。
- **主要测试对象**：主要针对 **Android 智能手机**。
- **衡量指标**：只测 **延迟 (latency)**，也就是单次推理所花的时间。
- **结果形式**：提供一个 **总结分数 (overall score)** 和排行榜。
- **局限性**：
    - 只关注延迟，不考虑准确率或能效等维度。
    - 没有 **质量目标 (accuracy target)**，因此不能保证不同设备结果的可比性。


**与 MLPerf 的对比**
- **AI Benchmark** → 只测延迟，没有质量约束，测试范围局限于 Android 手机。
- **MLPerf** → 我们的目标更广，涵盖 **IoT → 手机 → 边缘 → 服务器** 各种设备；  
    每个基准测试都有 **四个不同场景** (如单流、批处理、多流、离线)，而且带有明确的 **精度要求**。


**[EEMBC MLMark](https://zhida.zhihu.com/search?content_id=242670823&content_type=Article&match_order=1&q=EEMBC+MLMark&zhida_source=entity)**
。EEMBC MLMark[17]衡量**嵌入式推理设备**的性能和精度。它还包括**图像分类和目标检测**任务，就像MLPerf所做的那样，但它**缺乏用例场景**。MLMark以显式的批大小度量性能，而MLPerf允许提交者**为不同的场景选择最佳的批大小**。而且，前者没有目标质量限制，而后者有限制。

**[Fathom](https://zhida.zhihu.com/search?content_id=242670823&content_type=Article&match_order=1&q=Fathom&zhida_source=entity)**
Fathom[2]提供了一套包含**多个层类型**(例如，卷积、全连接和RNN)的模型。不过，它关注的是**吞吐量**而不是准确性。像Fathom一样，我们包含了一套包含不同层的模型。与Fathom相比，MLPerf同时提供**PyTorch和TensorFlow参考实现进行优化**，并引入了各种具有**不同性能指标的推理场景**。


**[AI Matrix](https://zhida.zhihu.com/search?content_id=242670823&content_type=Article&match_order=1&q=AI+Matrix&zhida_source=entity)**
。AI Matrix[3]是阿里巴巴的AI加速器基准。它使用微基准测试来涵盖矩阵乘法和卷积等基本操作，它测量全连接层和其他常见层的性能，它包括密切跟踪内部应用程序的完整模型，并且它提供了一个综合基准测试来匹配实际工作负载的特征。MLPerf有一个较小的模型集合，并专注于使用LoadGen模拟场景。

**DeepBench**。
微基准测试，如DeepBench[8]测量内核级操作(例如5,124×700×2,048 GEMM)的库实现，这对生产模型的性能很重要。它们对于高效开发是有用的，但是不能处理完整模型的复杂性。

**[TBD](https://zhida.zhihu.com/search?content_id=242670823&content_type=Article&match_order=1&q=TBD&zhida_source=entity)**
(dnn的训练基准)。TBD[57]是多伦多大学和微软研究院的一个联合项目，专注于机器学习训练。它在三个框架(TensorFlow、MXNet和CNTK)中提供了广泛的ML模型，以及用于改进它们的强大工具链。它专注于评估GPU性能，只有一个涵盖推理的完整模型(Deep Speech 2)。

**DAWNBench**。
DAWNBench[14]是第一个衡量深度学习系统端到端性能的多参与者基准竞赛。它允许跨模型体系结构、优化过程、软件框架和硬件平台进行优化。DAWNBench启发了MLPerf，但我们提供了更多的任务、模型和场景。

| 基准名称                  | 主要测试对象                     | 测试内容 / 任务                      | 衡量指标                 | 特点                                | 局限性 / 与 MLPerf 对比                                        |
| --------------------- | -------------------------- | ------------------------------ | -------------------- | --------------------------------- | -------------------------------------------------------- |
| **AI Benchmark [23]** | 移动设备（主要是 **Android 智能手机**） | 多个推理模型                         | **延迟 (latency)**     | - 第一个移动推理基准- 提供综合得分与排行榜           | - 只测延迟，无精度目标- 范围仅限 Android 手机- 与 MLPerf 相比：设备范围太窄，没有场景划分 |
| **EEMBC MLMark [17]** | **嵌入式推理设备**                | 图像分类、目标检测                      | 性能 + 精度              | - 专注嵌入式- 明确批大小                    | - **缺乏用例场景**- 没有目标质量限制- 与 MLPerf 相比：无法灵活选择批大小，限制较强       |
| **Fathom [2]**        | 通用深度学习模型集合                 | 多种层类型（卷积、全连接、RNN）              | **吞吐量 (throughput)** | - 提供丰富层类型- 用于比较不同模型结构             | - 不关注精度- 与 MLPerf 相比：缺少参考实现、缺少多场景                        |
| **AI Matrix [3]**     | AI 加速器（阿里巴巴提出）             | - 微基准（矩阵乘法、卷积）- 完整模型（贴近实际应用）   | 吞吐量 / 性能             | - 综合基准，涵盖微基准+完整模型- 与实际工作负载紧密联系    | - 模型集合较大但场景不够标准化- 与 MLPerf 相比：MLPerf 更强调 LoadGen 统一场景    |
| **DeepBench [8]**     | 内核级操作（算子性能）                | GEMM、卷积等内核                     | 运算性能                 | - 微基准，便于优化低层库                     | - 不能反映完整模型复杂性- 与 MLPerf 相比：粒度过低，不适合端到端性能评估               |
| **TBD [57]**          | 训练基准（多伦多大学 & 微软研究）         | 多个模型（训练为主），少量推理（Deep Speech 2） | 训练时间、GPU 性能          | - 覆盖多个框架 (TF, MXNet, CNTK)- 强大工具链 | - 主要面向训练，推理覆盖不足- 与 MLPerf 相比：不聚焦推理场景                     |
| **DAWNBench [14]**    | 端到端系统                      | 训练 + 推理                        | 时间到准确率、成本            | - 第一个端到端基准竞赛- 跨模型、框架、硬件           | - 任务、模型数量有限- 启发了 MLPerf，但覆盖面不够大                          |



- **AI Benchmark / MLMark / Fathom / AI Matrix** → 偏重 **推理性能**，但各自局限于延迟、吞吐量、嵌入式等维度。
- **DeepBench** → 偏 **底层算子性能**，不是端到端。
- **TBD** → 偏 **训练基准**，推理覆盖很弱。
- **DAWNBench** → **端到端性能竞赛**，奠定了 MLPerf 的思路，但覆盖不够全面。
- **MLPerf** → 融合这些基准的优点，统一框架，覆盖更广任务/设备/场景，且有精度约束和可比性。
